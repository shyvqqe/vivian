# Vivian — объединённая сборка (11 ноября 2026)

Собрана на основе `vivian-main (3).zip` с предыдущим патчем музыкальных команд и модерации. Из журнала Grok и фрагмента Meta AI взяты проверяемые идеи; отдельный архив с изменёнными файлами Grok не предоставлялся. В `commands/music_catalog.py` сохранён интерфейс `prepare(raw)` и `search(query, source, limit)`, но он адаптирован под проверки ссылок Vivian. Полный исходный бот сохранён.

## Возможности и команды

| Команда | Действие |
|---|---|
| `/play query` | Первый доступный трек YouTube/SoundCloud в очередь и запуск, если нет играющего трека |
| `!play <запрос>` | Немедленно заменить текущую музыку найденным треком |
| `/search query` | Поиск нескольких треков с выбором и сохранением в плейлист |
| `/queue`, `/skip`, `/pause`, `/resume`, `/stop`, `/volume`, `/loop`, `/playlists` | Управление плеером и очередью |
| `!queue`, `!skip`, `!pause`, `!resume`, `!stop`, `!volume`, `!loop` | Быстрые текстовые действия (очередь в виде короткой сводки) |
| `/mute user duration reason`, `!mute @user 10m причина` | Тайм-аут с сохранением в журнале наказаний |
| `/unmute user`, `!unmute @user` | Снятие **только** тайм-аута, выданного системой Vivian |
| `/ban`, `!ban @user причина` | Бан с проверкой прав и иерархии ролей |
| `/kick`, `!kick @user причина` | Удаление участника с проверкой прав |
| `/warn`, `!warn @user причина` | Предупреждение с действующей лестницей наказаний |
| `/tempmute`, `/tempban` | Оригинальные временные наказания Vivian |

Примеры музыкальных запросов:

```
/play query:Кино - Группа крови
/play query:spotify Pink Floyd - Speak To Me
/play query:apple Daft Punk - Get Lucky
/play query:яндекс Кино - Группа крови
/play query:вк Кино - Группа крови
/play query:https://youtu.be/ABCDEFGHI12
/play query:https://soundcloud.com/artist/track
/play query:https://open.spotify.com/track/6rqhFgbbKwnb9MLmUQDhG6
/play query:https://music.apple.com/us/album/example/123456789?i=123456789
/play query:https://music.yandex.ru/album/123/track/456
/play query:https://vk.com/audio-123_456
!play спотифай Pink Floyd - Speak To Me
!play саундклауд Artist - Song
```

## Реальные ограничения музыкальных сервисов

* **YouTube и SoundCloud** — источники воспроизводимого аудио через существующий relay или локальный `yt-dlp` + FFmpeg.
* **Spotify** — публичные ссылки на отдельные треки через официальный oEmbed; если oEmbed отдаёт исполнителя, он сохраняется в поисковом запросе. Для текстовых запросов воспроизведение ищется на YouTube.
* **Apple Music** — публичный iTunes Lookup API для ссылок на треки и iTunes Search API для текстовых запросов с префиксом `apple` / `эпл` / `айтьюнс`; звук ищется на YouTube.
* **Яндекс Музыка и VK Музыка** — текстовые запросы поддерживаются через YouTube. Для публичных ссылок на *отдельные треки* используются метатеги страницы, если они доступны. Когда метаданные отсутствуют, бот выдаёт понятную ошибку и просит название песни, **а не подставляет ссылку как вымышленную песню**.
* Плейлисты/альбомы сторонних каталогов не разворачиваются автоматически; приватные треки, DRM и защищённые каталоги не обходятся. Совпадение записи YouTube с оригиналом не гарантируется.

## Оптимизация

* Отложенное подтверждение `/play` и `/search`: главному циклу Discord не приходится ждать HTTP-метаданные или работу `yt-dlp` — поиск выполняется в рабочем потоке.
* Поисковые результаты `yt-dlp` / relay имеют кэш на ~90 секунд из предыдущего патча; метаданные Apple/Spotify также кэшируются в памяти процесса.
* Панели обновляются с объединением частых запросов. После начала воспроизведения ответ команды больше не ждёт отдельного Discord PATCH-запроса для панели.
* `app/messages.py`: известные `!play`, `!skip`, `!pause`, `!resume`, `!stop`, `!volume`, `!loop`, `!queue`, `!mute`, `!unmute`, `!ban`, `!kick`, `!warn` запускаются **после** модерации и старта наблюдателей, но **без** обработки как AI-диалога, записи в диалоговую память и лишнего ambient-шага. Проверки прав Discord остаются включены. Для зарегистрированных команд в личных сообщениях тоже есть короткий маршрут.
* Быстрые `!mute/!ban/!warn/!kick` используют **ту же систему**, что и slash-команды: новые серверные роли и права проверяются через Discord, без небезопасного кэширования разрешений.

*Нельзя гарантировать ускорение всех команд бота: сетевые лимиты, сервер Discord, работа `yt-dlp` и доступность сервисов влияют на задержку. Замеры на реальном сервере не проводились.*

## Установка

1. Для новой установки распакуйте полный архив. Для обновления существующего проекта распакуйте патч поверх той же корневой папки `vivian-main/`.
2. Создайте рабочий `.env` на сервере по `.env.example`; секреты **не** кладите в архив/репозиторий. Настройте `DISCORD_TOKEN`, БД и прочие сервисы по потребности.
3. Установите пакеты: `python -m pip install -r requirements.txt`. Понадобятся также системный **FFmpeg** и доступный JavaScript runtime **Node.js** для актуального `yt-dlp` (в `Dockerfile` оба предусмотрены).
4. `RELAY_URL` и `RELAY_TOKEN` необязательны; без них используется локальный `yt-dlp`. Для поиска Apple Music можно настроить двухбуквенный `APPLE_MUSIC_COUNTRY=RU` (например, `LV` или `US`).
5. В Discord Developer Portal включите необходимые **Message Content Intent** и **Server Members Intent**. Выдайте музыкальные права Connect/Speak и соответствующие Moderate Members, Ban Members, Kick Members. Роль бота должна быть выше ролей участников, на которых применяются наказания.
6. Запустите `python vivian.py` или соберите Docker-контейнер по `Dockerfile`. Slash-команды регистрируются при запуске, и Discord может показывать обновления не сразу.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m compileall -q .
```

Обработку каталогов, безопасные ссылки, fallback и кэш проверяют изолированные тесты без сетевого доступа. Для полноценного запуска потребуются зависимости, токены и Discord-сервер; голосовая сессия и реальная модерация здесь **не** проверялись.

`README-MUSIC-MODERATION.md` оставлен как история предыдущего патча; этот файл описывает объединённую сборку.

## Дополнение по журналу Grok (11 ноября 2026)

В переданном `.txt` есть трассировка работы Grok и результаты его проб: поиск через YouTube/iTunes, Spotify oEmbed, проверки API Яндекса/VK, создание `commands/fastmod.py`, ускоренная обработка DM, тесты фронтенда. **Файла `vivian-fast.zip` и исходников React-фронтенда в приложении не было.** Поэтому данная сборка — проверяемое продолжение предыдущего `Vivian_FINAL_2026-11-11.zip`, а не побайтовое слияние с недоступными файлами Grok.

Что реализовано на основе проверяемых идей Grok:

* Быстрый маршрут prefix-команд без обхода антиспама, AI-модерации, Discord permissions и системы предупреждений.
* Отдельные текстовые команды `!skip`, `!pause`, `!resume`, `!queue`, `!loop`, `!volume`. Обновление панели после ответа происходит асинхронно.
* `!mute`, `!unmute`, `!ban`, `!kick`, `!warn` продолжают обращаться к оригинальному хранилищу наказаний Vivian. Исправлено сообщение статуса при снятии мута (`released`).
* Воспроизводимое аудио остаётся с YouTube/SoundCloud, а Apple/Spotify/VK/Яндекс используются как каталоги и ссылки для поиска. Невалидные/закрытые ссылки не подменяются названием песни.

**Не переносилось:** созданное Grok веб-демо с интерфейсом поиска (нет его исходников), получение музыки из защищённых библиотек, неофициальные токены Spotify и закрытые API.

Новый патч `Vivian_GROK_PATCH_2026-11-11.zip` накладывается на **предыдущий Vivian FINAL**, а не на исходный архив `vivian-main (3).zip`.
