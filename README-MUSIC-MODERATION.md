# Vivian — музыка и модерация (обновление)

## Что изменилось

- `/play query` — запускает первый найденный трек немедленно, добавляя его в очередь. Больше не заглушка.
- `!play query` — сразу заменяет текущий трек, без дополнительного меню выбора источника.
- `/search query` — показывает до 10 кандидатов с выбором для очереди/сохранения плейлистов.
- `/playlists query` — прежняя панель поиска и плейлистов, теперь принимает новые форматы запросов.
- `/queue`, `/skip`, `/pause`, `/resume`, `/stop`, `/loop`, `/volume`, `!stop` — сохранены.
- `/mute user duration reason` — Discord timeout с сохранением случая в существующем журнале Vivian; для срока свыше 28 дней действует механизм продления.
- `/unmute user` — снять timeout, выданный через *систему Vivian*, не изменяя чужие наказания.
- `/ban`, `/kick`, `/warn`, `/tempmute`, `/tempban` — **уже были** в проекте и сохранены.

## Запросы

```text
/play query:Daft Punk One More Time
/play query:https://www.youtube.com/watch?v=...
/play query:https://soundcloud.com/artist/track
/play query:https://open.spotify.com/track/...
/play query:https://music.apple.com/us/album/example/123456789?i=123456789
/play query:https://music.yandex.ru/album/123/track/456
/play query:https://vk.com/audio-123_456
/play query:vk Artist - Track
!play spotify Artist - Track
!play soundcloud Artist - Track
/search query:apple Artist - Track
/mute user:@member duration:30m reason:Спам
/unmute user:@member
```

Префиксы источников: `youtube`, `yt`, `soundcloud`, `sc`, `spotify`, `apple`, `applemusic`, `vk`, `вк`, `yandex`, `яндекс`.

**Важно о лицензировании/технических ограничениях.** Spotify, Apple Music, VK Музыка и Яндекс Музыка здесь служат только источниками **публичных метаданных** (название трека), когда сервис позволяет получить их без авторизации. Аудиопоток из этих платных/защищённых каталогов не извлекается, DRM не обходится. Бот ищет совпадающую доступную запись на YouTube и воспроизводит её через уже существующий backend `yt-dlp`/FFmpeg/relay. Совпадение не гарантировано. Приватные ссылки и некоторые публичные VK/Яндекс URL могут не отдавать метаданные, в этом случае нужно отправить `название исполнителя - название трека` обычным текстом. Ссылки на альбомы и плейлисты Spotify/Yandex/VK не разворачиваются в набор треков.

## Установка

1. Замените файлы проекта содержимым этого архива, сохранив `.env` с секретами **вне** репозитория.
2. Установите зависимости из `requirements.txt` и FFmpeg; Dockerfile уже включает FFmpeg и Node.js.
3. Установите `DISCORD_TOKEN` и настройки подключения к БД, необходимые исходному боту. `RELAY_URL` и `RELAY_TOKEN` необязательны: без них используется локальный `yt-dlp`.
4. Дайте боту `Connect`, `Speak` для музыки и права `Moderate Members`, `Ban Members`, `Kick Members` для модерации. Роль бота должна быть выше ролей модерируемых, а Discord Developer Portal должен иметь включённые необходимые intents.
5. Перезапустите бот и дождитесь синхронизации slash-команд (время распространения определяется Discord).

## Что ускорено

- Команды `/play` и `!play` сразу выбирают один результат, не заставляя дополнительно открывать панель из 10 результатов.
- Кэш метаданных поиска на ~90 секунд, с защитой от мутации результатов.
- Метаданные ссылок обрабатываются в рабочем потоке (без блокировки главного asyncio loop).
- Убрана загрузка фоновой картинки при каждой простой prefix-команде музыки.
- Запросы свежих ролей и участников для проверки модерации выполняются параллельно; безопасность проверок сохранена.
- Частые обновления панели музыки сгруппированы, ограничены интервалом 1 секунда.

Ускорение не отменяет сетевую задержку Discord, DNS, yt-dlp, подключения к voice gateway и ограничений сторонних сервисов. Замеры на реальном сервере не выполнялись.

## Проверки без Discord

```sh
python -m unittest discover -s tests -v
python -m compileall -q .
```

Тесты проверяют обработку Spotify/Apple/VK/Yandex ссылок, безопасность доменов и кэш поиска, но не являются интеграционным тестом воспроизведения или модерации на Discord-сервере.
